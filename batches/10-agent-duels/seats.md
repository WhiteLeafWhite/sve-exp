# 两个座位怎样对练

主教位使用 `bishop`，主流位使用 `meta`。每三个对局组成一个循环，按破坏巫师、侮蔑龙、财宝皇室顺序使用同一份主教。每个对手的奇数局主教先攻、偶数局主教后攻。每五局复查额度并发布。双方均从玩家视角选择行动，裁判保存种子并在终局后写出可重演的原生录像。

从模拟器源码根目录运行以下命令，令 `$table` 指向本目录。负责裁判的一方用 `node $previous/prepare.mjs --duels` 构建引擎，随后用 `python $table/table.py block 1` 开始首组五局。参与者只打开本座位的界面。收到新局或轮到自己时，执行以下命令查看可见场面与选择。

```powershell
node "$table/seat.mjs" view bishop 30
node "$table/seat.mjs" view meta 30
```

每名参与者仅使用其中自己的角色。界面返回 `ticket`、双方公开区、自己的手牌、剩余 PP／EP／SEP 和合法选项。从 0 开始数，选择一项，附上基于当时可见信息的理由。一张已知的对方手牌如由公开检索或回手揭示，可据此推断。牌库顺序和未知手牌数量以外的信息由裁判保管。

录像的 `duel.viewVersion` 为 2 时，对方手里曾公开且按规则仍记得的牌会列在 `known` 字段，未知牌仍只给数量。早期未写此版本号的界面需要玩家根据此前公开动作自行记牌。分支重演沿用该局的视野版本。

```powershell
node "$table/seat.mjs" act bishop <ticket> <选项序号> step "留下 1 PP 给公开 EX 的水银的断绝"
node "$table/seat.mjs" act meta <ticket> <选项序号> turn "先保留偶像数量结算超进化，再决定献祭"
```

`step` 执行这一步，`turn` 将本回合后续选择交给该座位的策略，`game` 将本局后续选择交给该座位的策略。每方至少亲自作出一次实质主阶段选择，才可委托本局余下部分。裁判自动提交唯一合法动作及空 Quick 窗口。录像末尾列出双方手选次数、各自策略命中的选项、代行的公平预设，以及所有说明。续场从已提交的规则输入恢复，代行程序的内部搜索缓存会重建。

两个 seat 可分别编写自己的 `pilots/bishop.mjs` 或 `pilots/meta.mjs`，导出 `choose({seat,key,view,answers})`。策略仅依据座位视野，返回合法选项下标或 `null`（交给公平搜索）。主教可另导出 `baseRevision` 选择 r2、r3 或 r4。策略在一局开始时冻结，裁判保存内容指纹和源码快照。局中实际选项以 `seat.mjs` 为准。

如需试改牌表，把主教候选保存为 `decks/bishop.json`，主流候选保存为 `decks/<分享码>.json`。三个对手共用的主教于下一循环开始时冻结。在主流一侧，每个区域以相对最初原表的换入与移出张数之较大值计数，两区加总并计入主战者更换，最多五张。原表允许保有之前冻结的禁限例外。每局结束后，可在 `<分享码>/notes/NN-bishop.md` 或 `NN-meta.md` 写各自的复盘，下一次整理会把文字加入逐局手记。训练者在组间更新职业打法，构筑张数的变化归入构筑日志。

打满五场后，裁判运行 `python -B -X utf8 "$table/checkpoint.py" <组号>`。这一步逐局校验提交的两副实际牌表、策略快照、手选次数与双方的复盘，并把实战题写入对应职业的 `references/agent-duels.md`。达到周额度停止条件时，可传 `--through <最后一场完成的全局局号>` 整理不足五场的尾组。

赛后可从一处输入分支。`node "$table/branch.mjs" <已结束录像> 64 --inspect 64` 会列出当时的合法选项。用 `--picks 64=2,65=2,66=0 --out <新文件>` 替换主操作、目标和弃牌，后续交回该局存档的双方策略。程序检查断点前的手选与委托动作，并重建整局搜索状态。续场后重建过缓存的录像需要另行标出重置处。巫师首局从输入 64 不做替换，可以逐条复现完整原局。[替换歪曲的进步的实际录像](drills/rune-01-warped-progress.json)
